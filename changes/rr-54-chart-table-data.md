RR-54 (output-changing only for decks that use the new fields, or whose chart cells held non-numeric strings; needs core with RR-54, opf#376): chart and table data in the PPTX export and import (core `docs/chart-table-data.md`).
    - Strict chart numbers: every chart value passes core `chartNumber`, replacing the exporter's lenient parse (`"1e6"` exported as 16, `"(5)"` as 5, `"Q1"` as 1, `"12%"` as 12). A string that is not a plain decimal is a gap, reported once per chart as `chart-value-not-numeric` with the count. Import reads cached values with the same rule (XML decimal forms such as `+5` and `.5` stay numbers): a cache value that is no number is a gap and a `chart-value-not-numeric` diagnostic instead of a stripped number or 0.
    - Number formats: a column's `format` (DataColumn) is written as the series `c:numCache/c:formatCode`, the series data-label `c:numFmt` (`sourceLinked="0"`, except labels that show percentages), the value-axis `c:numFmt` (the first plotted series' format; a scatter X axis takes the X column's; a 100% stacked axis keeps `0%`), the chartex `cx:lvl formatCode`, value-label and value-axis `cx:numFmt`, and the embedded workbook cell formats, so Edit Data shows them. Dataset tables and number cells with a cell or column format export their formatted text; a DataColumn header exports its name.
    - Datasets and mapping: charts and tables resolve through core (`resolveChartData`, `inlineTableData`, `layoutTable` with the document), so a `{dataset, fields}` reference and `chart.mapping` (category, scatter X and series by column name) export exactly like their inline equivalent; core's `chart-mapping-adapted` warnings are reported on the chart's path.
    - Round trip (`full` provenance): `OPF_DATASETS_V1` beside the document tag keeps the whole `datasets` map, and `OPF_DATA_V1` on each chart or table frame that uses a new field keeps its authored data form (dataset reference, mapping, DataColumn formats, `data.source`, header and cell formats). Import restores them while the native evidence is unchanged (a chart's cache hash, a table cell's shown text) and otherwise keeps the native values and reports `chart-data-provenance-changed`, `table-data-provenance-changed`, `chart-dataset-unavailable` or `table-dataset-unavailable`. `references-only` and `provenance: false` write no data tags.
    - Import without provenance: a series format code that core `numberFormatFromExcel` maps back becomes that column's `{name, format}` (classic and chartex charts); any other code is reported as `chart-number-format-adapted` and never invented, and a data-label format equal to its series format is no longer reported as lost. Decks whose codes are `General` import unchanged.
    - A deck that uses none of the new fields (and only numbers or strict decimal strings in its charts) exports byte for byte as before (`test/fixtures/rr-54-unchanged.json`).
